The factory pins every outside input of its builds and its cluster (roadmaps 203 and 242): nothing moves until this card moves it. Bump each to the newest release of its line in one pull request, and check what each item says:

- **Outside images and charts**: `upstream-images.txt`. An image or OCI chart is its tag and its linux/amd64 digest (`crane digest --platform linux/amd64 <image>:<tag>`), an HTTP chart repository's archive or a file a pod needs its URL and sha256 (a chart's from the repository's index.yaml). Every reference names the store's copy of a line: the Dockerfiles' `FROM ${UPSTREAM}` lines here, while ci.yml and project-image.yml read their buildkit image from the list's `docker.io/moby/buildkit` line (`go test ./internal/reproducible` names a reference off the list and a workflow that carries a pin of its own), the infra repository's manifests, HelmReleases, chart sources and ts-go template there (its `scripts/upstream-images-test/test.sh`, which config-check runs). A line marked bootstrap (Forgejo, CNPG, cert-manager, local-path, Flux, Talos's Kubernetes, Cilium) is an upgrade of what Forgejo or the nodes run on: read its release notes first. Talos's and Cilium's lines move with their upgrade, and the infra re-seed runbook's hand installs (Cilium, the Forgejo and cert-manager charts) name the bootstrap digests too, which the infra test holds to the list.
- **Debian snapshot**: `DEBIAN_SNAPSHOT` in Dockerfile.runner and Dockerfile.sandbox, one snapshot.debian.org time for both, moved with the `debian:bookworm-slim` line.
- **PostgreSQL**: `POSTGRESQL_VERSION`, `LIBPQ_VERSION` and `POSTGRESQL_COMMON_VERSION` in both Dockerfiles, the versions bookworm-pgdg serves now, which apt-archive.postgresql.org keeps.
- **Go toolchain**: the patch release of go.mod's `toolchain` and of the golang lines, one Go for all (`TestDockerfilesBuildWithOneGo`).
- **Downloaded tools**: the lines of `upstream-files.txt` with the version ARGs and the `ADD --checksum` sums of Dockerfile.runner and Dockerfile.sandbox. No Go file holds a pin: the build VM and the factory stack read theirs from the lists.
- **Go vulnerability database**: `GOVULNDB_VERSION` and its `ADD --checksum` sum in Dockerfile.runner with the `govulndb` line of `upstream-files.txt`. The version is the `modified` time of https://vuln.go.dev/index/db.json.gz, written like `20261021T002729Z`; the sum is the sha256 of https://vuln.go.dev/vulndb.zip, downloaded just before the push, since the zip moves with the database and the copy before the checks refuses a sum its URL no longer serves. govulncheck itself is go.mod's tool: `go get -tool golang.org/x/vuln/cmd/govulncheck@latest`. A finding the new database brings is this card's to fix.
- **Template images**: the `upstream` lines of the ts-go template's `factory/images.yaml`, each to the newest release of its line, with the new URL and its sha256 (Go's from go.dev/dl, Node's from nodejs.org). The sandbox base follows the Debian snapshot bump by itself.

Before the checks of each head this pull request pushes, the factory copies into the store every line the head adds to either list, of every kind, and the Go module and npm tarballs of its go.sum and plugin lockfile, with main's scripts/upstream-copy and scripts/upstream-files. A line it cannot copy comes back on this card as a finding with what its URL served, such as `its URL does not serve the pinned sha256 <sum>`, or with the host the copy does not reach, and the pull request's checks then name the line the store lacks. Main CI's upstream job finds the copies in place after the merge. Only then can the infra repository's references move to the new lines, since a pod whose copy is missing does not start.
